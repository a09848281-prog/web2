# Remote Camera Web2 v3.0.0 Release

**Release branch:** `release/v3.0`  
**Release date:** 2026-11-25

## Network connection policy

1. **Direct-first:** Web and Android first gather host and server-reflexive candidates using STUN only. TURN candidates are not offered during this attempt.
2. **IPv6 direct retry:** If the first direct attempt fails and a global IPv6 candidate is available, a separate IPv6-only direct attempt is made.
3. **ExpressTURN fallback:** TURN credentials are enabled only for the final relay retry. The selected route remains visible in the WebRTC diagnostics.

The Web offer carries a validated ICE mode through GAS signaling metadata. GAS adds a trailing `metadataJson` field to the Signals sheet; existing columns and rows are retained. Clients that do not send a mode remain compatible with the older all-candidates behavior.

## Monthly TURN traffic meter

The Web page shows estimated monthly send, receive, and total traffic. It counts bytes from the selected candidate pair only when either side of the pair is a TURN relay. Values are stored by month in the controller browser's local storage.

This is an estimate based on browser WebRTC statistics, not ExpressTURN's official billing total. Different browsers and controller devices are not automatically combined. TURN protocol overhead and provider-side accounting may differ.

## Camera field-of-view consistency

- The `original` capture ratio is now derived from Camera2's active sensor area, falling back to the pixel-array area and finally to a supported output format.
- If the exact requested ratio is unavailable, camera-format fallback prioritizes the closest aspect ratio before comparing pixel counts.
- Android applies saved quality/FPS/aspect settings before the first capture source and PeerConnection are created. This avoids opening the camera at a default profile and immediately replacing it during connection setup.

TURN does not itself crop or modify video frames. The relay forwards encrypted WebRTC packets; a narrower picture is normally caused by camera output size, crop region, lens selection, or viewer fit mode. The new sensor-ratio and capture-order changes target those likely sources, but the Galaxy A22 5G still needs an on-device comparison for final confirmation.
