# Remote Camera Web2 v2.7.1 Preview – Reservation, Recovery, Camera Controls

Branch: `preview/v2.7.1-fixes`  
Version: `2.7.1-preview` / Android versionCode `430`  
Package ID unchanged: `jp.a09848281.remotecamera.v26`

## Fixes

- Web connection reservations accept seconds (`datetime-local step=1`) and are checked by a 250 ms foreground-page scheduler. Browser/PWA suspension or force-closing the page can delay a Web reservation; this does not wake a suspended iPad browser.
- The Web viewer retries failed first connection attempts after the user has armed Connect. Manual Disconnect still disables automatic retry.
- Android APK start/end schedules are saved with exact alarms and seconds. Saved schedule times synchronize to the GAS Settings row and appear in the Web reservation panel. If the APK has not yet registered its device ID/secret, synchronization is deferred until service initialization.
- APK schedules are restored after reboot, app replacement, and exact-alarm permission changes when Android permits it. Camera and microphone permissions must already be granted.
- **Android background restriction:** an exact alarm can qualify for the general background foreground-service start exception, but it does not remove camera/microphone while-in-use permission rules. Android 14+ generally requires the app to be visible when creating a camera/microphone foreground service, subject to documented exemptions. On Android 13 and earlier the service may be created but camera/microphone access can still be restricted when the app is backgrounded. Therefore the scheduled APK start must be tested on the actual phone with the screen off; the code does not claim to bypass Android's permission model.
- The active WebRTC Camera2 repeating request now sets `FLASH_MODE_TORCH`, avoiding the separate `CameraManager.setTorchMode()` call that can fail with `CAMERA_IN_USE` while the camera is streaming.
- FPS options now include 40, 45, 50, and 55 in Web and APK settings. The selected camera capture format is reported back; devices may fall back to a supported lower FPS or resolution.
- Camera format changes compare requested settings with the previous requested profile, not the actual fallback FPS, preventing repeated restart loops on devices that cannot reach the selected FPS.
- Re-enabling the camera builds a new supported capture profile and updates the actual capture information.

## Setup changes

1. Update the Google Apps Script deployment with `gas/Code.gs` (API `1.3.0`) and redeploy the Web App.
2. Install the new APK build from the `remote-camera-web2-preview-v2.7.1-apk` GitHub Actions artifact. Its package ID remains compatible with the existing app.
3. Refresh the PWA at `https://a09848281-prog.github.io/web2/v2.7.1/`. Close and reopen the PWA if its service worker retains old files.
4. In Android settings, grant exact-alarm access if Android requests it. Camera and microphone permissions must be granted before scheduling a start.

## Limits

- The Web reservation requires the Web page to be active; browsers can suspend JavaScript timers in the background.
- Exact alarms are subject to Android's special-access permission and OEM power policies. A user force-stop, revoked camera/microphone permissions, while-in-use restrictions, or OS restrictions can still block a scheduled camera start.
- A device cannot capture faster than its Camera2 hardware and AE FPS ranges allow. 40/45/50/55 are selectable targets, not guaranteed output rates.
- In-stream torch behavior still needs a physical Android test; a successful APK build does not certify Galaxy A22 5G camera firmware behavior.
