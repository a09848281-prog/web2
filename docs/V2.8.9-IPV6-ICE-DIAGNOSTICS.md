# Remote Camera Web2 v2.8.9 — IPv6 ICE再試行・接続診断

## 目的

v2.8.8のCloudflare TURN対応を維持したまま、IPv6候補を利用した接続再試行と、ブックマークレット欄内の診断表示を追加します。異なるWi-Fi間で接続できる可能性を高め、接続失敗時に原因を確認しやすくします。

## 接続方式と再試行順

1. 通常接続：IPv4・IPv6の両方の候補をWebRTCに収集させます。Cloudflare TURNが設定済みならTURN候補も取得します。
2. IPv6優先の再試行：通常接続が失敗し、Web側でグローバルIPv6候補を取得できている場合に限り、そのIPv6候補だけを含むOfferを1回送信します。
3. TURN中継の再試行：IPv6で接続できない、IPv6候補がない、またはIPv6優先接続が失敗した場合、Cloudflare TURNが設定済みならTURN relay-onlyで再試行します。
4. 通常方式へ復帰：TURNでも接続できなければ通常方式へ戻します。再試行を無制限に重ねず、既存の自動再接続間隔・監視処理に従います。
5. 接続が30秒安定したら、次回障害に備えてIPv6/TURN再試行状態をリセットします。

IPv6はWebRTCが取得できたグローバルIPv6候補だけを使用します。IPv6がない環境ではIPv6再試行を行わず、設定済みTURNへ進みます。

## STUN・TURN

- Google公開STUNを標準候補として使用し、IPv4/IPv6候補の発見を補助します。
- Cloudflare TURNの設定はv2.8.8の方式を維持します。GASが有効期限付き認証情報を発行し、長期SecretはGAS Script Properties内だけに保存します。
- Cloudflare TURN未設定・APIエラー時も、STUNによる直接接続を継続します。ただしTURN中継へ切り替えられないため、別Wi-Fi間で接続できない場合があります。
- STUNのみでは、対称NAT、UDP制限、強いファイアウォールなどを必ずしも越えられません。Cloudflare TURNも未設定時は全ての異なるWi-Fi環境での接続を保証できません。
- Cloudflare TURNの料金枠・利用量はCloudflare側で確認してください。TURNを有効にした場合、実際のTURN中継通信量が発生します。

## Android APK

Android APKは既存のGAS device_pollからICEサーバー情報を取得し、RtcEngineがSTUN/TURN URLと認証情報をWebRTCに適用します。今回の変更ではAndroid側のRTC実装を変更していないため、IPv6/TURN設定のためのAPK再インストールは不要です。実際に利用できるIPv6アドレス・候補はAndroid OSとWi-Fiルーター側の設定にも依存します。

## ブックマークレット内の診断

「ブックマークレット」ダイアログのコード欄の下に「ICE・IPv6接続診断」を表示します。

表示項目：
- 接続段階、試行モード（通常 / IPv6優先 / TURN中継）
- ICE gathering / ICE connection / Peer connection / Signaling の状態
- Web側とAndroid側の候補数
- IPv4・グローバルIPv6・その他IPv6の候補数
- host / srflx / prflx / relay候補数
- 選択中の通信経路（IPv4 / IPv6 / 中継）と候補種別
- TURNの状態、直近の診断履歴、最終エラー

プライバシー：生のIPアドレスは診断欄へ表示・保存しません。診断コピーにもIPアドレスは含めません。

## 更新手順

1. Apps Scriptで既存プロジェクトのCode.gsを、このブランチのgas/Code.gs全体で置き換えます。
2. 保存し、「デプロイ」→「デプロイを管理」→既存Webアプリの編集→「新バージョン」→「デプロイ」を行います。既存の/exec URLは維持します。
3. v2.8.8でCloudflare TURNを設定済みの場合、同じGAS Script Properties（CF_TURN_KEY_ID / CF_TURN_KEY_SECRET）を維持します。まだ設定していない場合はV2.8.8-CLOUDFLARE-TURN-ICE.mdを参照してください。
4. GitHub ActionsのDeploy PWA to GitHub Pagesを選び、ブランチpreview/v2.8.9-ipv6-ice-diagnosticsを指定して実行します。
5. iPadのWeb/PWAを再読み込みします。必要に応じてホーム画面PWAを終了して再度開きます。
6. AndroidをWi-Fi A、iPadをWi-Fi B（別の回線またはテザリング）へ接続して試します。
7. 失敗した場合、ブックマークレット欄の「診断を更新」→「診断をコピー」で診断結果を共有してください。

## 自動テストと実機確認

network-ice.jsのアドレス分類・候補解析・候補集計・IPv6候補フィルター・候補なし時の安全な停止をNode.jsテストで検証します。GAS Cloudflare TURN認証情報のサーバー側管理、キャッシュ、URL検証、期限付き認証情報の発行も回帰テストします。Webの既存機能・AndroidビルドもGitHub Actionsで確認します。

GitHub Actionsの成功はソース検査・自動テスト・APKビルドの成功を意味し、別Wi-Fiの実端末接続を実証したものではありません。最終確認にはGalaxy A22 5GとiPadを異なるネットワークへ接続した実機テストが必要です。
