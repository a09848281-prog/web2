# Remote Camera Web2 v2.8.9 — IPv6 ICE再試行・接続診断

## 目的

Cloudflare TURNや外部TURNサーバーを使わず、異なるWi-Fi間で接続できる可能性を高めます。通常のWebRTC接続が失敗した場合、ブラウザーが取得できたグローバルIPv6候補だけを使って1回再試行します。

## 通信方式

1. 通常接続：IPv4・IPv6の候補をWebRTCに収集させ、取得できた候補をAndroidへ送ります。
2. ICEが失敗した場合：Web側でSDPの候補を解析します。
3. Web側にグローバルIPv6候補がある場合：IPv6候補だけを含むOfferを作り、Androidへ新しいセッションとして送ります。
4. Android側のAnswerとICE候補を受信し、IPv6で接続できるか確認します。
5. IPv6候補がない、または接続できない場合：通常のIPv4/IPv6自動方式へ戻します。IPv6再試行を無限に繰り返しません。

Android APKは既存のSTUN設定受信・WebRTC候補収集機能を利用するため、この変更ではAPKの更新は不要です。

## STUN・TURN

- 使用するのはGoogle公開STUNのみです。
- TURNサーバー、Cloudflareキー、TURN用Script Propertiesは不要です。
- GASはSTUNサーバー一覧を返します。AndroidとWebの映像・音声はWebRTCで直接接続します。
- STUNは接続先候補の発見を助ける仕組みで、映像を中継しません。

**制約：** STUNのみでは、対称NAT、UDP制限、強いファイアウォール、IPv6未提供などの環境で接続できない場合があります。IPv6を使うには、両端末がグローバルIPv6候補を取得でき、通信が許可されている必要があります。全ての別Wi-Fi環境での接続を保証するものではありません。

## ICE診断の表示場所

Web画面の「ブックマークレット」ダイアログ内にある「ICE・IPv6接続診断」に表示します。

表示内容：
- 接続段階、試行モード
- ICE gathering / ICE connection / Peer connection / Signaling の状態
- Web側とAndroid側の候補数
- IPv4・グローバルIPv6・その他IPv6の候補数
- host / srflx / relayの候補種別数
- 選択された経路のIPファミリーと候補種別
- 直近の診断履歴とエラー

IPアドレスそのものは表示・保存しません。「診断をコピー」で共有する場合も、生のIPアドレスは含みません。

## 更新手順

1. Apps Scriptで現在使用しているプロジェクトの Code.gs を、このブランチの gas/Code.gs 全体で置き換えます。
2. 保存し、「デプロイ」→「デプロイを管理」→既存Webアプリの編集→「新バージョン」→「デプロイ」を行います。既存の /exec URLは維持してください。
3. GitHub Actionsで Deploy PWA to GitHub Pages を選び、ブランチ preview/v2.8.9-ipv6-ice-diagnostics を指定して実行します。
4. iPadのWeb/PWAを再読み込みします。必要に応じてホーム画面PWAを一度終了して再度開きます。
5. AndroidをWi-Fi A、iPadをWi-Fi B（別の回線またはテザリング）へ接続して試します。
6. 失敗した場合は、ブックマークレットダイアログ内の「診断を更新」→「診断をコピー」で診断を共有してください。

## テスト

network-ice.js はアドレス分類、候補解析、件数集計、IPv6候補フィルター、候補がない場合の安全な失敗をNode.jsテストで検証します。GAS設定がGoogle STUNのみであること、HTML診断パネルとService Workerキャッシュの整合性も自動チェックします。

GitHub Actionsのソース検査・Androidビルドが成功しても、実端末同士の別Wi-Fi接続まで実証したことにはなりません。最終確認にはGalaxy A22 5GとiPadを異なるネットワークへ接続した実機テストが必要です。
