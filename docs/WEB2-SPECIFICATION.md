# Remote Camera Web2 仕様書 v1.1.0
作成日：2026-11-21 / 対象：Galaxy A22 5G・Android 13、iPad PWA、PC Web / 個人利用

## 1. 構成
- Android：KotlinネイティブAPK、Foreground Service、WebRTC
- iPad / PC：GitHub PagesのHTML/CSS/JavaScript PWA
- ペアリング・初期シグナリング：GAS + Google Sheets
- 映像・音声：WebRTC RTP/SRTP
- 接続後の操作・設定・状態・診断：WebRTC DataChannel
- Firebase / FCM / 外部AI API：不使用
- 映像録画・音声録音・静止画保存・メディア履歴：実装しない
- 既存 `a09848281-prog/web` は変更しない

## 2. 接続方式
1. Androidを前面で開き、必要な権限を確認して利用者が待機を開始。
2. 待機中はカメラ・マイクを停止し、APKで指定した秒数の間隔でGASへ接続要求を確認。
3. Androidに8桁・10分有効・一回限りのペアリングコードを表示。
4. Web側でコードを入力し、操作端末をペアリング。
5. WebがOfferとDataChannelを生成し、GASを使って初回SDP/ICEを交換。
6. AndroidがAnswerを返す。
7. DataChannelがOPENになった後、接続中のカメラ・音声・設定・ACK・テレメトリー・診断はDataChannelで直接送受信する。
8. 最大3台のWeb操作端末を同時監視できるよう、Android側に空き接続枠（3台未満）がある間だけ、Androidは指定間隔でGASへ追加の接続要求を確認する。追加接続要求がない場合も、ライブ操作自体はGASへ送らない。
9. 3台が接続中なら追加要求のGAS確認を停止し、いずれかの接続が終了して空き枠ができたら再開する。RTCが切断して再シグナリングが必要な場合もGASを利用する。
10. WebRTCのメディアはGASを通さない。公開STUNを必ずフォールバックとして使用し、必要に応じてGAS Script PropertiesのTURN_URLS / TURN_USERNAME / TURN_CREDENTIALからTURN設定を取得する。TURNサーバー自体は別途必要で、GASはTURN中継を行わない。

## 3. Androidバックグラウンド待機
- APKの画面にはペアリングコード発行・再発行、GAS問い合わせ間隔、バックグラウンド開始・停止だけを配置する。
- GAS問い合わせ間隔は1〜50秒、初期値10秒。1秒指定は可能だがGAS実行回数と電池消費が非常に増える。
- Foreground Serviceと継続通知を使用。
- 待機中はカメラ・マイクを停止。
- DataChannel接続後のライブ操作・設定・状態送信はDataChannelを使う。最大3台のWeb操作端末を受け入れるため、接続台数が3台未満の間だけ、追加接続要求を指定間隔でGAS確認する。3台接続中は追加確認を停止し、空き枠ができると再開する。
- Doze、省電力モード、メーカー独自制御で指定秒数より遅れる場合がある。
- 強制停止、端末電源OFF、権限取消、圏外では遠隔接続を保証しない。

## 4. 映像・カメラ
- Androidカメラのリアルタイム映像配信
- 背面 / 前面カメラ切り替え
- 端末が対応する範囲で解像度・FPS・ビットレート変更
- 16:9などの表示比率、全画面表示
- Camera2 APIで取得できるカメラID・焦点距離を列挙し、端末が公開する広角・標準・望遠などのレンズをWebから切り替える。端末が複数レンズを公開しない場合は前面・背面のみとなる。
- Web表示ズーム（100～300%）は表示中ブラウザー内だけのデジタル拡大。Androidセンサー側ズームではなく、ほかの閲覧端末の映像には影響しない。
- 暗所表示補正はWeb表示の明るさ・コントラスト補正。Androidカメラの露出時間やISOを直接変更するハードウェア夜間撮影ではない。
- ライトON/OFFはAndroid CameraManagerと背面フラッシュ対応機器で提供
- 切断時は古い映像をライブとして表示し続けない
- 録画・静止画保存なし

## 5. 音声
- AndroidマイクからWebへのリアルタイム音声
- Web PTTからAndroidへのリアルタイム音声
- Androidスピーカー音量0～100
- マイク送信ゲイン0～100
- マイク感度/自動ゲイン要求0～100
- ノイズ抑制要求0～100
- ミュート・PTT
- 録音保存なし

**重要な制限：** Android標準NoiseSuppressorや一般的なWebRTC音声制御は、全端末で連続的な0～100の実効強度を保証しない。現在の実装では値を要求値として保存し、対応するON/OFF型の処理は音声ソース初期化時に反映する。音声ゲインは接続中に調整できる。スライダー数値と実際の抑制量が比例するとは限らない。

## 6. DataChannelの操作
接続後にDataChannelで送る操作：
- カメラ切り替え
- 画質・FPS・ビットレート
- スピーカー音量
- マイクノイズ抑制要求・感度要求・送信ゲイン
- 夜間モード要求
- 位置情報の一回取得
- 診断要求
- 切断要求
- 命令ACK、端末状態、通信量

DataChannelがない接続前の段階だけGASを使う。設定保存などの管理データはGAS/Sheetsへ保存する場合があるが、接続中の即時操作はDataChannelを優先する。

## 7. 追加機能
- 動体検知：Web側で受信映像の縮小グレースケール画像を一定間隔で比較。一定の変化が連続したときに動体イベントとする。
- 動体検知感度5段階、誤検知抑制のため連続検出とイベント間隔制限を使用。
- 検知時刻・動体スコア・感度・検知元だけをMotionEventsシートへ保存。画像・サムネイル・動画・音声は保存しない。
- 複数Web閲覧端末で同じカメラの動きを同時検知した場合、同じ検知元かつ3秒以内のイベントはGAS側で1件にまとめる。
- MotionEventsはAndroid端末ごとに直近2,000件を保持し、上限を超えたとき最古のイベントを削除する。
- 検知履歴の表示、CSV出力、履歴削除、対応ブラウザーでの通知（通知権限は利用者が許可）。
- 動体検知はWeb画面が映像接続中かつ表示中にだけ動作。Webタブを閉じた状態やバックグラウンド中の検知は保証しない。
- 人物認識・人物候補推定・移動方向推定・エリア侵入検知・複数監視領域は実装しない。
- 夜間表示補正（実際のカメラ露出制御ではなくWeb画面上の補正）。
- 端末温度・熱状態監視
- 低バッテリー/高温時の負荷低減
- 接続予約（指定時刻にブラウザーから接続を試行。Web画面が動作中で、OSがブラウザー実行を許可している場合に限る）
- 通信断時の自動復旧（Web側で最大5回再接続を試行）
- 複数Android端末の登録・選択
- ブックマークレット起動（認証情報を含めず、前回の端末を選択状態で開く。カメラは自動起動しない）
- 通信量・画質モード
- WebRTC統計（RTT・パケット損失）に応じた自動画質・ビットレート調整。連続した品質悪化時に負荷を下げ、安定時に段階的に戻す。画質または通信量モードをAutoにした場合だけ動作。
- 同時視聴中の切断操作はセッションIDで対象PeerConnectionを限定する。ひとつのWeb端末を切断しても他のWeb端末を終了させない。
- 接続中の追加Web端末を確認するGASポーリングは、設定した1～50秒の間隔を守る。満員時は低頻度の空き枠確認だけを行う。
- GAS Script Propertiesに設定したTURN URL・ユーザー名・認証情報を、認証済み端末にだけ返す。認証情報はGitHubに含めない。

## 8. 通信量・ネットワーク診断
- Androidの登録済みWeb操作端末は最大3台。各ブラウザーは別々のcontrollerTokenで認証する。
- 旧Webの濃紺ヘッダー・左サイドバー・右ライブビュー・地図表示を引き継ぐ。
- 旧Webで実装したペアリング、複数端末選択、ライブ映像、双方向音声、PTT、前面・背面および端末対応レンズの切替、ライト、位置情報・履歴、履歴削除、音量、画質・FPS・表示比率、全画面復帰、通信量、接続予約、再接続、通信統計、診断機能を維持する。
- 映像の全画面表示はPeerConnectionを作り直さず画面表示だけを切り替え、解除時の映像停止を防ぐ。
- 映像解像度・FPS（10/15/24/30/60要求値）・表示比率（16:9/4:3/1:1/元比率）をWebから選択できる。FPSと解像度の実際の利用可否は端末カメラの対応範囲に依存する。
- WebRTC DataChannelがOPENになった時点でAndroidアプリUID通信カウンターを基準化。
- Androidから送信量、受信量、合計、速度を2秒ごとにDataChannel送信。
- Android UID統計はアプリ全体の通信を含むことがあり、WebRTCだけの通信量と一致するとは限らない。
- Web側はgetStats()でRTP送受信量、RTT、パケット損失を表示。Android側で捕捉した接続・命令エラーはネットワーク診断情報と一緒にDataChannelで返信する。
- Android側診断：ネットワーク種別、validated状態、metered状態、信号強度（取得可能な場合）、ローカルIP、DNS、インターフェイス、Androidバージョン、端末モデル、RTCチャネル状態。
- エラー時に診断要求を送る。DataChannelが切断している場合は、再接続後に再取得。
- Wi-Fiパスワード、deviceSecret、controllerToken等の認証秘密情報は診断に含めない。
- 取得できない情報は「取得不可」とする。

## 9. 安定性・安全
- Foreground ServiceはSTART_STICKYでプロセス終了後の復旧を要求し、GAS初期登録失敗時は待機中に自動再試行する。
- ライブPeerConnectionが1つ以上ある間だけPARTIAL_WAKE_LOCKを使用し、最後のセッション終了後に解放。
- ICE DISCONNECTEDが8秒継続したセッションは終了・リソース解放して再接続可能な状態に戻す。
- ユーザー操作の端末切替中に既存PeerConnectionと選択端末の識別情報が混ざらないよう、接続中の端末切替を拒否。
- DataChannel送信失敗を操作成功として扱わない。

- 権限拒否、Foreground Service開始失敗、不正SDP、カメラ形式不対応、RTC生成失敗を個別に捕捉。
- カメラ・音声・DataChannel・PeerConnectionの終了処理は多重実行に耐えるようにする。
- 位置情報権限は任意。未許可でも待機を開始できる。
- カメラ・マイク利用はAndroidの通知とプライバシー表示で確認できる。
- Android OSの強制停止や権限制約を回避しない。
- 実機Logcatテストなしにクラッシュゼロを保証しない。
