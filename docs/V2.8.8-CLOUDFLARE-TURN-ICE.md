# Remote Camera Web2 v2.8.8 – Cloudflare TURN / 異なるWi-Fi間の接続

## 今回の修正

- GASがCloudflare Realtime TURNの有効期限付きICE認証情報をサーバー側で発行する。
- Cloudflareの長期TURN key secretはGASのスクリプトプロパティだけに保存し、GitHub・Web・APKへ含めない。
- 発行した認証情報はGASのScript Cacheに最大6時間保存し、Androidの定期ポーリングでCloudflare APIを毎回呼ばない。
- 認証情報の有効期限は48時間。Cloudflareが許可する上限に合わせる。
- 非trickle ICEでタイムアウトの原因になり得るポート53と、Cloudflare以外のTURNホストを除外する。
- 既存の手動TURN設定（TURN_URLS / TURN_USERNAME / TURN_CREDENTIAL）はフォールバックとして維持。
- WebのICE候補収集待ちを8秒から20秒へ延長し、接続処理監視を90秒へ延長。
- 接続統計に選択された通信経路（TURN中継 / 直接経路 / 未確定）を表示する。
- まず通常の直接接続を試し、ICE失敗時は自動再接続でTURNリレーのみを使う方式へ切り替える。これにより、不要なTURN通信量を避けつつ別Wi-Fi間の接続性を高める。
- Android APKは既にGASから受け取るICEサーバーJSONを解析し、turn: / turns: URLとusername/passwordをPeerConnectionへ適用できるため、APKの接続実装は変更しない。

## Cloudflare側の準備

Cloudflare Realtime TURNはGoogleのSTUNとは異なり、NATやファイアウォールで直接通信できない場合にメディアを中継するサービスです。Cloudflareの公開資料では、TURN転送量1,000GBまでは無料枠、その後は従量課金です。無料枠を超える利用には料金が発生するため、Cloudflareアカウント側の利用量・請求設定を確認してください。

1. Cloudflareにサインインし、Realtime / TURNの画面でTURN keyを作成する。
2. TURN keyのID（UID）を控える。
3. 作成されたTURN keyの「UID」と「Secret / Key」を控える。
4. Secret / Keyは作成直後にしか表示されない場合があるため、安全な場所に保管する。通常のCloudflare API Tokenを別途作成する必要はありません。

## GASに秘密情報を登録

既存のRemote Camera GASプロジェクトを開きます。

1. 左側の歯車「プロジェクトの設定」を開く。
2. 「スクリプト プロパティ」→「スクリプト プロパティを追加」。
3. 次の2項目を追加する。

| プロパティ | 値 |
|---|---|
| CF_TURN_KEY_ID | Cloudflareで作成したTURN keyのUID |
| CF_TURN_KEY_SECRET | そのTURN keyのSecret / Key（Bearer token） |

4. 保存する。
5. GASエディタ上部の関数選択で testCloudflareTurnSetup を選び、実行する。UrlFetchApp の権限確認が出たら許可する。
6. 実行ログに turnConfigured: true / turnProvider: cloudflare が表示されることを確認する。falseの場合はTURN keyのUIDとSecret / Keyの値を見直す。

TURN keyのSecretをGitHubのファイル、Android APK、Webのconfig.jsonへ貼り付けないでください。

## APKについて

Android側は MonitorService.kt がGASの device_poll から iceServers を受け取り、RtcEngine.kt が各ICEサーバーのURL・username・credentialを読み込む設計です。そのため、Cloudflare TURNの設定はGAS経由で既存APKにも反映され、TURN対応だけを理由にAPKを再インストールする必要はありません。

Androidのアプリ版は引き続き 2.8.6-preview（versionCode 435）です。今回の変更ではAPKの実装を変更していません。

## 確認手順

1. GASのスクリプトプロパティ登録と新バージョンのデプロイを完了する。
2. GitHub Pagesをデプロイする。
3. AndroidをWi-Fi Aへ接続し、アプリで監視待機を開始する。
4. iPad / PCを別のWi-Fi、またはスマートフォンのテザリングへ接続する。
5. Web2からペアリング済みAndroidを選び「接続」を押す。
6. 映像・音声・制御チャネルが接続されることを確認する。

同じWi-FiでもTURNを必ず使うわけではありません。直接経路が成立すれば直接通信、難しい場合にTURN中継へ切り替わります。

## 注意事項

- Cloudflare TURNは1,000GBの無料枠を超えると従量課金です。映像は通信量が大きくなるため、使用量を確認してください。
- TURNはメディア通信を中継しますが、GASが保存するペアリング・シグナリングの仕組みは従来どおりです。
- 直接接続が失敗した場合はWeb側が次の再接続でTURN中継のみを使うモードへ切り替えます。手動で新しく接続する場合は通常の自動選択へ戻します。
- CloudflareのTURN認証情報は最大48時間で期限切れになります。期限切れ等でICEが切断された場合、既存の自動再接続で新しい認証情報を取得して再接続します。切断時間が完全にゼロになることまでは保証できません。
- GitHub Actionsによる構文・回帰テストとAPKビルドは実行できますが、異なるWi-Fiを使った実機通信テストは、Android端末とiPad/PCの実ネットワークで確認する必要があります。
